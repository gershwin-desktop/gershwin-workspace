# Assertions: P-smart (Spotlight smart folders, .savedSearch)

Status: [S] public docs (Apple "File Metadata Query Expression Syntax"), [F:E36] fixture or observation of the 10.6.8 Finder (Tests/GWMetadata/interop/fixtures/finder106/E36-smart-folders), [M] needs a Mac (OPEN for Scout).

## File format
- S1 [F:E36] A .savedSearch is an XML plist. Read keys: RawQuery (else RawQueryDict.RawQuery), RawQueryDict.SearchScopes (else SearchCriteria.FXScopeArrayOfPaths), RawQueryDict.FinderFilesOnly / UserFilesOnly, CompatibleVersion (a value above 1 is refused with a message, not guessed). SearchCriteria.FXCriteriaSlices is the Finder's editor model; it is neither read nor needed to run the search (hand-crit opens without slices). Test: t_SavedSearch "files and scopes".
- S2 [F:E36] SearchCriteria is MANDATORY: a file without it crashes Finder 10.6.8 (SIGSEGV on open). The writer always writes CompatibleVersion 1, RawQuery, RawQueryDict {RawQuery, SearchScopes}, SearchCriteria {AnyAttributeContains "", FXScope, FXScopeArrayOfPaths} plus CurrentFolderPath for a folder scope, and no FXCriteriaSlices (hand-crit, which the Finder opened and showed with an empty criteria bar). FXScope 'SCev' 1396925814 for the computer, 'SCcf' 1396925286 for a folder. FinderFilesOnly / UserFilesOnly are written only if the file we read had them (hand-crit had neither). Several folders are not written (the FXScope for them is unknown). Test: t_SavedSearch "E36". OPEN [M]: the Finder's reaction to our own written files (not yet tried); FinderInfo flags 0x0010 and ~/Library/Saved Searches are not set by the library, only the Find window creates the folder.
- S3 [S] Scopes: kMDQueryScopeComputer (and ComputerIndexed) = search everywhere indexed; kMDQueryScopeHome = home; absolute path = that folder. kMDQueryScopeNetwork and anything else are listed as unsupported. FinderFilesOnly / UserFilesOnly are reported in the notes as not applied.

## Query language (RawQuery -> MDKit)
- Q1 [F:E36] Grammar (the Finder leaves values unquoted: `kMDItemContentTypeTree = public.content`, `_kMDItemGroupId = 13`; wraps queries in `(true) &&` / `&& (true)`; dates are CFAbsoluteTime reals; names are `kMDItemDisplayName = "*x*"cd`): comparisons `attr op value` with == = != < > <= >=, && || ! and parentheses, InRange(attr,lo,hi), strings in "..." or '...' followed by modifier letters, numbers, $time.* functions. Test: t_SavedSearch.
- Q2 [S] String modifier c = case insensitive (MDKit "c"); no c = case sensitive, as in Spotlight. d (diacritics) and w (word) are NOT applied and are reported in the notes. `*` is the only wildcard; values with %, ?, [ (and _ when case insensitive) are unsupported because MDKit passes the text to SQLite LIKE/GLOB where these are wildcards that Spotlight does not have.
- Q3 [S] ! is pushed to the comparisons (De Morgan, inverted operator) because MDKit has no NOT. != stays != (for multi-valued attributes the two are not the same in Spotlight; only single-valued attributes are in the table).
- Q4 [S] Attributes translated (exact MDKit name checked against attributes.plist by test): kMDItemFSName, kMDItemDisplayName (note: searched as file name), kMDItemFSSize, kMDItemFSContentChangeDate -> GSMDItemFSModificationDate, kMDItemFSCreationDate, kMDItemTextContent, kMDItemFinderComment, Title, Authors, Keywords, Description, Album, Composer, MusicalGenre, PixelHeight, PixelWidth, NumberOfPages, DurationSeconds.
- Q5 [S] kMDItemContentTypeTree / kMDItemContentType with a UTI from a fixed table: public.folder/directory -> file type directory, com.apple.application(-bundle) -> file type application, the others by lower case file name extension list (public.image, public.audio, public.movie, public.plain-text, public.source-code, com.adobe.pdf, a few leaf types). Reported in the notes as "matched by file name extension". Unknown UTIs are unsupported. A container UTI with kMDItemContentType (leaf match) is unsupported.
- Q6 [F:E36 for reals and InRange, S for the units] Dates: $time.now(secs), $time.today(days), $time.yesterday, $time.this_week(weeks), this_month(months), this_year(years), $time.iso(...), resolved when the search is opened (noted); MDKit stores seconds since the reference date. OPEN [M]/E35: the offset unit of $time.today(-7) (days assumed from the documentation) and whether this_week starts on the locale's first weekday.
- Q7 [S] Never guess: any unsupported term (unindexed attribute such as kMDItemFSLabel, kMDItemKind, kMDItemLastUsedDate; text ordering; malformed text) means NO MDKit query is produced, every unsupported term is listed (GWSavedSearch -unsupportedTerms, -statusText), and the search is not run. Dropping a term would silently return other files than the Finder shows.
- Q8 [F:E36] kMDItemFSLabel = 6 (red): the label lives in Finder Info / xattr and is not in the gmds index, so it is unsupported until the extractor indexes it (not in P-smart's files).

## Saving (MDKit -> RawQuery)
- W1 [S] +savedSearchWithMDKitQuery:searchPaths:error: converts MDKit text with the inverse table (GSMDItemFSExtension x -> kMDItemFSName == "*.x"c, file type directory/application -> kMDItemContentTypeTree 'public.folder' / 'com.apple.application', dates -> $time.iso(...Z)). An attribute without a Spotlight spelling gives nil and a message, no guess. Test: t_SavedSearch "writing" (round trip through the forward translation).
- W2 OPEN [M]/E35: 10.6 Finder opening our written file; kMDItemFSName vs kMDItemDisplayName for names; $time.iso accepted.

## MDKit fixes found on the way (t_MDKParse)
- M1 MDKQueryScanner treated "<=" as "<" and ">=" as ">" (the shorter operator was tried first), so every <= / >= query failed to parse. Fixed: longer operator first.
- M2 The parser's state was a function static, so after any query in a process the next query's first comparison raised "subquery without compound operator". Fixed: per scanner instance.

## Run
- R1 GWSavedSearchRunner runs the translation through MDKQuery (raw results) and reports result paths to a delegate; it does not start a search that has unsupported terms. Verified to start and finish against a live gmds; NOT verified to return paths: the gmds index on the build machine was empty. OPEN: the raw result line format (assumed one path per line) needs a run on a machine with an index.

## E36 additions
- E1 [F:E36] `_kMDItemGroupId = 13` is kind Image (canned All Images; Finder-written files) and 9 is kind Folder (canned Today and Past Week: "None of: Kind is folders"). Both are translated (the image extension list, the directory file type); any other group id is unsupported. kMDItemContentTypeTree = public.content (canned All Documents) and kMDItemLastUsedDate (Today, Yesterday, Past Week) are unsupported and named in the window.
- E2 [F:E36] kMDItemContentModificationDate (the Finder's "Last modified") is searched as the file modification date (note). Test: finder-written-Saved-Searches fixture.
- E3 MDKit does not index size, dates and owners (they are file system filters, applied only after a text query and not accepted alone). The translation therefore splits the query: size and date terms that are top level "and" terms are checked on the files the index returns (GWSavedSearch -fileTerms, exact to the second and byte, in the runner); inside an "or", under a negation that does not flatten, or alone they are unsupported. Verified live (isolated index): size > 12, modified before a date.
- E4 gmds result lines are arrays: the path first, then the score. Verified against an index of a temporary folder (a separate test user's home; the user's own index was not touched).
- W3 The Find window writes through GWFindCriteria: Name (contains, is, not contains, starts, ends; case sensitive like the module; no *), Size (the module compares whole KB), Kind (folder, application), modified and created dates (today, within as $time.now(-n), before, after, exactly as absolute day bounds). Contents, annotations, owner, other kinds, non recursive searches and several folders are refused by name. Test: Tests/FindCriteria.
